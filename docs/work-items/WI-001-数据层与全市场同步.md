## 1. 目标与范围

**目标**：搭起工程骨架与数据层，把 A 股全市场（股票 + ETF）的 10 年日 K 落到本地 SQLite，为后续选股与回测提供可查询的数据底座。

**范围内**：

- Maven 工程骨架、依赖、配置、SQL 迁移（自研迁移器）
- 标的字典同步（新浪全市场列表）
- 日 K 全量初始化（腾讯，按日期分段拉 10 年）
- 日 K 增量更新（含**除权检测**）
- 同步审计（`sync_log`）与异步任务表（`task`）
- 单元测试与一次小样本真实验证

**范围外**：

- 分钟级行情、港美股、公告与事件数据（二期）
- 指标计算与因子表（M3）
- 页面（M2 起）
- 全量 6,600 标的的正式同步执行（代码就绪后由用户择时触发）

### 2.2 Provider 接口

```java
public interface QuoteProvider {
    String name();
    List<DailyBar> fetchDailyBars(String instrumentId, LocalDate start, LocalDate end);
}

public interface SnapshotProvider {
    String name();
    List<InstrumentSnapshot> fetchAllInstruments();
}
```

约定：

- `fetchDailyBars` 返回按 `trade_date` **升序**，已换算到契约单位（股、元、小数）
- 无数据的标的不抛异常，返回空列表
- **条数校验在 Provider 内完成**：单次请求返回条数与预期不符即抛 `DataIntegrityException`
- 限速、重试、超时封装在 Provider 内部，业务层无感

### 2.3 除权检测

前复权价在每次除权后会整体重算，因此增量同步必须检测：

```
拉取最近 N 条 → 与库中重叠日期逐条比对 close
  ├─ 全部一致 → 仅追加新日期
  └─ 存在不一致 → 判定发生除权 → 该标的全量重拉并覆盖
```

比对不通过且重拉仍失败 → 标记该标的 `STALE` 并记录告警，**不得静默通过**。

## 3. 数据语义

| 项 | 值 |
|---|---|
| 市场 / 币种 / 时区 | A 股 / CNY / Asia/Shanghai |
| 复权方式 | 前复权（qfq），单一价格口径 |
| 数据来源 | 腾讯 `fqkline`（日K）、新浪 `Market_Center`（标的字典与快照） |
| 可用时点 | 交易日收盘后（15:00） |
| 单位与精度 | 价格元（REAL）、成交量股（INTEGER）、百分比小数 |

## 4. 实现要点

1. **腾讯单次上限 800 条**（≈3.2 年），10 年历史必须按日期区间分段，每标的约 4 段。
2. **腾讯字段顺序是「开收高低」**，不是常见排列；成交量单位是「手」。
3. **失败整批拒绝**：校验不通过时不写部分数据，避免产生难以发现的缺口。
4. **upsert 幂等**：`INSERT ... ON CONFLICT (instrument_id, trade_date) DO UPDATE`。
5. **分批提交**：每 500 条一个事务。
6. 请求限速默认 5 QPS（间隔 200ms），重试 3 次（退避 1s/2s/4s）。

## 5. 异常、幂等与回滚

- **异常**：单标的失败不中断整批，记录到 `sync_log`；任务结束时汇总失败数。校验类失败抛 `DataIntegrityException`（不可重试），网络类抛 `DataSyncException`（可重试）。
- **幂等**：全部写入走 upsert；重复执行同一区间的同步不产生重复行。
- **回滚**：本工作项只新增表和代码，不改动既有数据。回滚 = 删除 `data/finance.db` 重新初始化，或回退代码提交。数据库文件不入版本控制，无数据回滚风险。

## 7. 未验证项与剩余风险

- **全量 7,220 标的的完整同步未执行**。按 50 只耗时 75s 外推，全量约 3 小时（每只 4 段请求）。实际耗时与失败率待首次全量后回填
- **数据库体积超出预估**：实测 30 MB / 50 只 → 全量约 4.4 GB（原预估 2 GB）。主因是 SQLite 索引与页开销；后续补全成交额/换手率后还会增长。磁盘尚有 225 GB 可用，不构成阻塞
- 腾讯日K**不提供成交额与换手率**，当前两列为 NULL。需用新浪快照补全，已列入后续工作
- 交易日历表已建但**尚未回填**；增量同步当前用「最近 30 天窗口 + upsert 幂等」代替，未依赖日历
- `listed_at` 由日K最早交易日近似，对 10 年前已上市的标的会偏晚（值等于查询区间起点而非真实上市日）。若选股用到「上市天数」因子需注意此偏差
- `board` 由代码前缀推导（`BoardClassifier`），未与交易所官方分类核对
- 退市股不在本期范围
