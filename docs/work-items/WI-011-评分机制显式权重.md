## 1. 目标与范围

**目标**：把「条件」与「评分」拆开——条件只负责过滤，是否参与排序、方向与权重由用户显式指定，
替代 WI-005 中「数值条件自动参与评分、等权、方向由运算符推断」的隐式口径。

**范围内**：

- DSL 条件新增可选字段：`score` / `weight` / `direction`（见 §2.1）
- `DslValidator`：新增评分字段校验（见 §2.3）
- `ScreenerService`：显式模式判定、加权评分公式（选股与回测共用）
- 选股页条件卡：数值条件新增「评分」勾选、权重、方向控件
- 策略 JSON：新策略保存显式字段；旧策略保持兼容模式、行为与哈希不变
- 测试：权重公式手算对拍、方向覆盖、仅过滤不评分、eq 显式方向、校验失败

**范围外**：

- 评分分布口径（仍为命中集内相对百分位，WI-005 §2.1 不变）
- 布尔条件参与评分、权重按 IC/IR 自动推导、机器学习打分
- 评分结果落库、回测引擎代码（引擎仍调用同一评分路径）

## 2. 契约

### 2.1 DSL v2 字段（单条条件）

```json
{"factor":"return20","op":"gt","value":0,"score":true,"weight":2,"direction":"higher"}
```

| 字段 | 类型 | 缺省 | 语义 |
|---|---|---|---|
| `score` | boolean，可空 | 无（兼容模式） | `true` 参与评分；`false` 仅过滤 |
| `weight` | number，可空 | `1` | 评分权重，`0.1 ~ 10`；仅在 `score=true` 时允许出现 |
| `direction` | `"higher"` / `"lower"`，可空 | 由运算符推断：`gt/gte→higher`，`lt/lte→lower`；`eq` 无默认、必须显式给出 | 数值越大/越小得分越高 |

### 2.2 模式判定与评分公式

- **显式模式**：任一条件携带非空 `score` 字段。仅 `score=true` 的条件参与评分；
  `not` 组与布尔条件不允许 `score=true`（见 §2.3）。
- **兼容模式**：所有条件都缺 `score` 字段（旧策略 JSON）。完全沿用 WI-005 口径：
  数值 + `gt/gte/lt/lte` 自动参与、方向按运算符、权重 1——旧策略行为与策略哈希不变。
- **单条件得分**：与 WI-005 §2.1 相同（命中集内相对百分位；NULL 不参与；any 组仅在该行满足时参与）。
- **总评分**：`100 × Σ(wᵢ·pᵢ) / Σ(wᵢ)`，四舍五入保留 1 位小数；
  无任何参与条件或全部取值为 NULL 时为 NULL。
- **排序与分页**：不变（评分降序、NULL 最后、同分按 `instrument_id`、每页 50）。
- **回测**：`ScreenerService.evaluateAt` 走同一评分路径，无独立口径。

### 2.3 校验规则（DslValidator）

| 场景 | 结果 |
|---|---|
| 布尔因子 `score=true` | 拒绝：布尔因子不支持参与评分 |
| `not` 组条件 `score=true` | 拒绝：排除组条件不支持参与评分 |
| `score=true` 且 `weight` 缺失/非有限/超出 `0.1~10` | 拒绝：权重必须在 0.1 ~ 10 之间 |
| `score=true` 且 `direction` 非法值 | 拒绝：评分方向不合法 |
| `score=true` 且 `op=eq` 且 `direction` 缺失 | 拒绝：等值条件参与评分需指定方向 |
| `score` 缺失或 `false` 且出现 `weight`/`direction` | 拒绝：只有参与评分的条件才能设置权重/方向 |

### 2.4 数据语义

| 项 | 值 |
|---|---|
| 评分时点 | 与 WI-005 相同（筛选同一截面；回测按 `asOf`） |
| 持久化 | 不落库；字段随策略 JSON 保存；旧策略无需迁移 |
| 可比性 | 显式模式下评分权重可跨策略对齐；分布仍在命中集内，跨策略绝对值仍不可比 |

## 3. 实现要点

1. `Condition` 增加 `score`/`weight`/`direction` 三个可空字段，保留 3 参构造器兼容既有调用。
2. `ScoreDirection` 枚举（`higher`/`lower`）提供 JSON 小写键与 `defaultFor(CompareOp)`。
3. `ScreenerService.scoringConditions` 按模式解析参与条件；`score()` 改为加权平均。
4. 前端 `screenerApp`：数值条件序列化显式字段；旧策略载入时按兼容口径预置为显式勾选状态，
   保存后行为不变。
5. 评分控件仅出现在 `ALL`/`ANY` 组的数值条件上。

## 4. 异常、幂等与回滚

- **异常**：校验失败抛 `BusinessException`（页面提示）；评分查询失败走 `WebExceptionHandler`。
- **幂等**：查询只读；同 DSL 同数据重复执行结果一致。
- **回滚**：纯代码 + 前端改动，无数据迁移；回退代码即可。已保存的新策略 JSON 含未知字段时，
  回退后的旧代码忽略未知字段（`@JsonIgnoreProperties(ignoreUnknown = true)`），退化为兼容模式评分。

## 6. 未验证项与剩余风险

- 权重需要用户自行设定，缺乏 IC/IR 等数据驱动依据；权重过大可能集中于单一因子
- 评分分布仍在命中集内，命中数小（<5）时百分位区分度低（WI-005 遗留）
- 命中集内的因子缺失值按「不参与该条件」处理，权重实际会被重归一化
- 1 位小数抹平小于 0.05 的差异，展示同分即按代码排序
