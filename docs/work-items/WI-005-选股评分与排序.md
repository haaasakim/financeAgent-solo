## 1. 目标与范围

**目标**：给选股结果加「评分」，按评分降序排列——越强烈满足条件的标的排前，
替代原先按股票代码排序；结果表增加「评分」列。

**范围内**：

- 评分口径：命中集内的**相对百分位**（见第 2 节）
- `ScreenerService`：命中集合（≤5,000）内计算评分、排序、服务层分页
- `ScreenerQueryMapper`：明细不再 SQL 分页；新增按白名单表达式取因子值
- 结果片段：新增「评分」列
- 测试：评分口径手算对拍、排序、并列与无评分回退、页面渲染

**范围外**：

- 数据库结构（评分查询时派生，不落库）
- DSL / 策略表结构（评分不写入策略 JSON）
- 自定义权重评分（后续如需要再升级）
- `not` 组与布尔条件参与评分（见 §2）
- 回测评分（M5）

## 2. 契约

### 2.1 评分口径（相对百分位）

- **候选集**：本次命中的全部标的（即筛选结果，上限 5,000）。
- **参与条件**：`all` 与 `any` 组中「数值因子 + `gt/gte/lt/lte`」的条件；
  布尔因子、`eq` 数值条件、`not` 组不参与评分（只做筛选与排除）。
- **方向**：`gt/gte` 越大越好；`lt/lte` 越小越好（方向由运算符推断，与用户设条件的意图一致）。
- **单条件得分**：对条件 c，设命中集中该因子非 NULL 的值集合为 V（n = |V|），
  标的取值 v：
  - 越大越好：`p = n == 1 ? 1 : count(V 中 < v) / (n - 1)`
  - 越小越好：`p = n == 1 ? 1 : count(V 中 > v) / (n - 1)`
  - v 为 NULL：该标的该条件不参与
- **any 组条件**只在该标的确实满足该条件时才参与；`all` 组条件全部参与。
- **总评分**：`100 × 各参与条件 p 的平均`，四舍五入保留 **1 位小数**（与展示一致，
  数学上同分的行不会因浮点末位差被拆开）；没有参与条件时为 NULL（页面显示 `--`）。
- **排序**：评分降序；无评分的排最后；同分（1 位小数相同）按 `instrument_id` 升序（稳定）。
- **分页**：每页仍固定 50；超过 5,000 条仍只展示计数（WI-004 §2.4 不变）。

### 2.2 展示

结果表列改为 8 列：代码 / 名称 / **评分** / 最新价 / 涨跌幅 / PE-TTM / PB / 20日收益。
评分保留 1 位小数；无评分显示 `--`。

### 2.3 数据语义

| 项 | 价值 |
|---|---|
| 评分时点 | 与筛选同一截面（`factor_daily` 每标的最新一行 + `market_snapshot`） |
| 数值单位 | 因子值使用库内原始口径（百分比因子为小数），评分前不换算单位 |
| 持久化 | 不落库；每次查询按当前命中集重算 |
| 可比性 | 仅在同一次筛选的命中集内可比；命中数越小区分度越低 |

### 2.4 路由与接口

路由不变（WI-004 §2.4）。`ScreenerResult` 结构不变，rows 变为服务层排序分页后的结果。

## 3. 实现要点

1. **白名单不变**：取因子值仍用注册表 `expression`（`${}` 仅限白名单表达式），阈值不参与该查询。
2. **单条件取数**：每个参与评分的因子取一次全市场值（`findFactorValues`），
   在内存中按命中标的过滤；不做逐标的查询。
3. **服务层分页**：命中集 ≤5,000，内存排序分页成本可忽略；SQL 只负责过滤与投影。
4. **评分不改变命中集合**：只影响 rows 的顺序与展示，`total` 与筛选条件不变。

## 4. 异常、幂等与回滚

- **异常**：评分查询失败抛 `DataAccessException`，走 `WebExceptionHandler`；DSL 校验路径不变。
- **幂等**：查询只读，重复执行结果一致（同数据同条件）。
- **回滚**：纯代码改动，回退到 WI-004 代码即可；无数据迁移。

## 6. 未验证项与剩余风险

- 相对评分只在命中集内可比；命中数为 1 时评分恒为 100
- 评分方向由运算符推断：若用户用反向条件表达（如「PE ≥ 10」），评分方向可能与主观意图不同
- 命中样本很少（如 2~3 只）时百分位区分度低，属口径预期
- 1 位小数抹平小于 0.05 的差异，展示相同即视为同分并按代码排序
- 沪深两市场未做行业中性化；评分不构成投资建议
- 分页改到服务层后，超过 5,000 条仍只计数（与 WI-004 一致）
