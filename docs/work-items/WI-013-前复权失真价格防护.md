| 日期 | 2026-09-15 |

## 1. 背景（发现于批量回测）

腾讯前复权采用「逐次减现金分红」的加性口径，高分红标的的**历史价格会趋零甚至为负**
（如 000937.SZ 2018-2021 年、000408.SZ 2019-2021 年、000651.SZ 2016 年）。
这批数据不是同步错误，而是前复权口径的固有结果，但引擎未做防护，暴露三类问题：

1. **除零崩溃**：0 价 bar 导致 `预算 / 价格` 抛 `/ by zero`（任务 174）。
2. **假成交**：负价买入得到负股数，卖出现为「负 × 负 = 正」金额，凭空产生盈利
   （任务 10/100/165/181/182 共 18 笔已成交记录价格 ≤ 0）。
3. **组合膨胀与空转**：失真价格扭曲净值后，买入试算的「减整手」循环迭代次数爆炸，
   任务卡死（任务 173：1457 个交易日仅推进 460 天）。

## 2. 目标与范围

**目标**：回测引擎按「价格失真 = 不可交易」处理前复权失真段，保证：
成交价格恒为正、净值不被失真价格污染、任何数据都不会导致崩溃或死循环。

**范围内**（仅 `backtest` 模块）：

- `PriceBook`：失真判定与窗口、有效收盘价回退
- `BacktestEngine`：买入 / 卖出 / 止损 / 盯市 / 目标集合的防护
- `BacktestTrade`：新增未成交原因「价格失真」
- 引擎测试；`DATA_CONTRACT` 补充前复权失真语义

**范围外**：

- 修复或替换前复权序列本身（需要复权因子表与全量重算，另行立项）
- 数据同步端的价格合法性校验（同属后续数据质量任务）
- 历史已产生任务的重新评估（完成后另行重跑）

## 3. 契约

### 3.1 失真判定

- **失真 bar**：任一行情字段 `open / high / low / close ≤ 0`（或 `pre_close ≤ 0`）。
- **失真标的**：回测区间内出现过任一失真 bar 的标的，**整段不可交易**。
- 为什么不做「失真后 250 根恢复」的局部窗口：前复权失真在首次非正价**之前**同样存在
  （价格被累计分红压低但恰为正）。例如 000408.SZ 于 2019-05-14 以 0.227 元（真实价约 7 元）
  被买入，随后长期停牌/失真，恢复后按真实价卖出，凭空产生 +436 万元收益——
  局部窗口无法可靠圈定这类压缩正价段，故对失真标的做整段排除。

### 3.2 引擎行为

| 场景 | 行为 |
|---|---|
| 买入成交日遇失真 | 订单作废，原因「价格失真」（不再递延，避免以失真价补成交） |
| 卖出成交日遇失真 | 订单延后（同停牌语义），但正常路径下不应出现（整段不可买） |
| 止损 / 时间止损 | 失真标的跳过检查（不以失真收盘价触发） |
| 目标集合 | 失真标的从候选中整段剔除（不占槽位，顺延下一名） |
| 盯市估值 | 取**最近一个有效（>0）收盘价**；全序列无有效价才视为数据异常抛错 |
| 买入试算 | 保留整手递减循环，最多 10,000 次；仍未满足现金约束则按「现金不足百股」作废 |

### 3.3 绩效口径

不变；`PerformanceMetrics` 已有的除零防护（夏普标准差为 0、年化基数 ≤ 0、换手均值为 0）继续有效。

## 4. 实现要点

1. `PriceBook` 预计算每标的不可交易集合：区间内出现任一失真 bar 即整段排除；
   判定结果按标的缓存，`tradableAt` 为 O(1) 查找。
2. `PriceBook.closeAt` 向前跳过非正收盘（有界回退，最多 250 根），保证盯市价为有效价。
3. `BacktestEngine.targets()` 增加 `priceBook.tradableAt` 过滤；执行路径加 `usableBar` 与
   `tradableAt` 双重防护。
4. 单元测试覆盖：负价 / 0 价 bar 不产生成交与假盈利、失真标的不进目标、
   失真标的整段不可交易、盯市回退到有效价。

## 5. 验证

**测试命令与结果**：

```
./mvnw test
→ Tests run: 191, Failures: 0, Errors: 0, Skipped: 0   BUILD SUCCESS
（新增 PriceBookTest 4 例：整段排除判定、0 价失真、盯市回退、有效价全无；
  BacktestEngineTest 补 2 例：负价标的不进目标不产生假盈利、0 价 bar 不再除零）

真实库回归（script/batch_backtest.py，20 任务全量重跑）：
→ 修复前：深度乖离回归 BEAR DAILY 因失真价格卡死（1457 天仅推进 460 天）；
  修复后同一任务 2 分钟内完成，结果由伪 +302.8% 修正为 -82.4%
→ 修复后全部任务的成交明细中，失真标的成交笔数为 0
→ 任务 173/174（旧版本）已标记失败并说明原因，未删除历史记录
```

**发现过程（供后续同类问题参考）**：
批量回测暴露三个现象——任务 174 抛 `/ by zero`（0 价 bar）、任务 173 CPU 占用高但进度停滞
（负价买入使净值膨胀，买入整手试算循环迭代爆炸）、若干任务有价格 ≤ 0 的已成交记录
（负股数 × 负价格 = 正金额，凭空盈利）。根因是前复权加性口径产生的失真价格。

## 6. 未验证项与剩余风险

- 整段排除是保守折中：19 只标的（约占全市场 0.6%）在任何含失真 bar 的区间内
  完全不可交易，其失真期之外的正常历史数据也一并放弃
- **首次非正价之前的压缩正价段**是本次踩坑点（000408.SZ），整段排除已覆盖；
  但若某标的的失真价格始终为正、从未跌破 0（理论上存在），仍无法识别
- 未修复数据本身；若后续引入复权因子表（乘法复权，不会为负），可改用真实价格
  序列并删除本防护
