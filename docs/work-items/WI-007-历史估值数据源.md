# WI-007 历史估值数据源（PE-TTM / PB-MRQ）

## 基本信息

| 项 | 值 |
|---|---|
| 编号 | WI-007 |
| 标题 | 东财历史估值日序列：估值因子回测数据源 |
| 日期 | 2026-09-13 |
| 状态 | VERIFIED |
| 风险等级 | 高 |

## 1. 目标与范围

**目标**：补齐逐日历史 PE-TTM / PB-MRQ，使含估值条件的策略（如示例策略「低估值+趋势转强」）可回测；也为后续历史时点选股提供数据基础。

**范围内**：

- 新增 `valuation_daily` 表与迁移 V6（追加式变更）
- 新增 `ValuationProvider` 接口与东财 `datacenter-web` 实现
- 同步任务：`--valuation.init`（全量回填）、`--valuation.update`（增量）；`--sync.incremental` 成功后自动衔接增量
- 回填对象：**已有日K的股票（STOCK）**；ETF 无估值数据，不采集
- 因子注册表：`peTtm` / `pb` 增加回测历史表达式（引用 `valuation_daily`）
- 回测校验：策略含估值因子时，若所选开始日期早于估值数据最早日期，给出用户可见提示

**范围外**：

- PS、股息率、ROE 等其他财务/估值字段（后续按需扩展）
- 采集历史总市值/股本（回测不依赖市值）
- 用当前快照 PE/PB 近似历史（属未来函数，禁止）

## 2. 契约

**数据源（实测 2026-09-13）**：

```
GET https://datacenter-web.eastmoney.com/api/data/v1/get
    ?reportName=RPT_VALUEANALYSIS_DET
    &columns=SECURITY_CODE,TRADE_DATE,PE_TTM,PB_MRQ
    &filter=(SECURITY_CODE in ("600000"))             # 或 (TRADE_DATE>='yyyy-MM-dd')(TRADE_DATE<='yyyy-MM-dd')
    &pageNumber=1&pageSize=5000
    &sortColumns=TRADE_DATE&sortTypes=-1              # 倒序
    &source=WEB&client=WEB
```

- `pageSize` 服务端上限 10,000；使用 5,000 更稳
- 600000 约 2,111 条（单页取全），最早约 2017-11（以实际为准）
- **限流教训**：多代码大批量 + 深分页（page ≥ 5）会被服务端连接重置并触发数分钟冷却；
  因此全量走逐代码单页、增量走逐日分片，不构造大结果集深分页（详见 `DATA_SOURCES.md` 第 7.1 节）
- ETF（如 510300）返回 `success=false, code=9201, message=返回数据为空`，视为「无数据」而非失败
- `TRADE_DATE` 格式 `2026-09-11 00:00:00`，取前 10 位为交易日

**表结构（V6 迁移，新增）**：`valuation_daily`

| 列 | 类型 | 说明 |
|---|---|---|
| instrument_id | TEXT | 与 `instrument` 关联 |
| trade_date | TEXT | 交易日（主键之一） |
| pe_ttm | REAL | 市盈率 TTM，倍；**非正数视为无效，存 NULL** |
| pb_mrq | REAL | 市净率 MRQ，倍；非正数存 NULL |
| source | TEXT | `EASTMONEY_DATACENTER` |
| fetched_at | TEXT | 抓取时刻 |
| data_status | TEXT | `ACCEPTED` |
| created_at / updated_at | TEXT | |

主键 `(instrument_id, trade_date)`；索引 `valuation_daily(trade_date)`。

**任务与接口**：

| 入口 | 说明 |
|---|---|
| `--valuation.init` | 遍历有日K的 STOCK，全量分页抓取并 upsert；任务名 `VALUATION_INIT` |
| `--valuation.update` | 按各标的库内最大交易日增量抓取；任务名 `VALUATION_UPDATE` |
| `--sync.incremental` | 成功后依次衔接因子增量与估值增量 |

**因子表达式（FactorRegistry）**：

- 最新截面（选股，保持不变）：`peTtm = ms.pe_ttm`、`pb = ms.pb`
- 历史截面（回测，新增）：`peTtm = v.pe_ttm`、`pb = v.pb_mrq`；
  回测查询以 `LEFT JOIN valuation_daily v ON v.instrument_id = i.instrument_id AND v.trade_date = f.trade_date` 取当日值，缺失为 NULL（条件不成立）

## 3. 数据语义

| 项 | 值 |
|---|---|
| 市场 / 币种 / 时区 | A 股股票（STOCK）/ CNY / Asia/Shanghai |
| 复权方式 | 与价格无关；估值按名义价格计算，东财原值直接存储 |
| 数据来源 | 东财数据中心 `RPT_VALUEANALYSIS_DET` |
| 可用时点 available_at | 该交易日收盘后（与日K一致），仅用于 `trade_date <= T` 的截面 |
| 单位与精度 | 倍；REAL；亏损/负值不落库（NULL），禁用 0 填充 |

## 4. 实现要点

- `ValuationProvider`：`fetchByCodes(codes)` 逐代码单页拉取（pageSize 5,000 一次取全单只历史），
  `fetchByDate(from)` 逐日分片拉取；两者都做**条数校验**：解析行数必须等于响应 `count`，
  不一致抛 `DataSyncException` 触发重试与整批拒绝。深分页已被实测证明会被服务端重置连接，禁止使用。
- `ValuationSyncService`：先全部抓到内存再写库，单标的失败只记 WARN 并继续，
  任务结束汇总成功/无数据/失败；每 500 只打进度日志；每 2,000 行一个事务 upsert。
- 失败整批拒绝的粒度是**单个标的**（全量）或**单日窗口**（增量）：全部成功才写库。
- 增量：先补齐「无记录或最新记录落后超过 30 天」的标的（逐代码全量），
  再从全市场最新估值日次日起按日抓取；无记录走全量。

## 5. 异常、幂等与回滚

- 空数据（`code=9201` 或 `count=0`）按成功跳过，不计失败；ETF 不在目标内。
- 重复执行幂等（主键 upsert）；不修改既有表；回滚只需停用新任务与新表。
- 估值缺失不阻塞因子与回测：回测中该日该因子为 NULL，相关条件不成立。

## 6. 验证

**验收标准**：

- 真实库回填后，抽样标的的 `valuation_daily` 与东财页面/接口逐位一致；不存在 0 值估值。
- 估值条件策略可回测，信号日取当日 PE/PB（不取最新快照）。
- 无日K的标的不会被采集；重复执行任务不产生重复行。

**边界覆盖**：正常 / ETF 空数据（9201） / 条数不符整批拒绝 / 超时重试 / 增量幂等 / 负值置空 / 回测区间覆盖校验

**实现修正**：

- 初版按「50 代码一批 + pageSize 10000」构造大结果集深分页，被服务端连接重置并触发分钟级冷却；
  改为**逐代码单页（pageSize 5,000）全量 + 逐日分片增量**，实测稳定（约 2 只/秒，0 失败）。
  该教训已写入 `docs/DATA_SOURCES.md` 第 7.1 节。
- 被重置后同一 JVM 的 HttpClient 连接池会持续失败（curl 正常），重启进程并冷却后恢复。

## 7. 未验证项与剩余风险

- 历史覆盖始于约 2018 年（全库最早 2018-01-02，各家略有差异），更早区间的估值策略无法回测（回测校验会提示）
- 跨新交易日的增量尚未在实盘日期验证（本次回填最新为 2026-09-11，下个交易日收盘后自动衔接）
- PE-TTM 的盈利口径由东财定义，与新浪快照可能有小幅差异（同一交易日不同抓取时点）
- 停牌日东财仍可能有估值行（价格未变），与 `factor_daily` 无行不一致；回测以 `factor_daily` 截面为准，不影响
- 回填只覆盖当时已有日K的股票；后续补全日K的新标的需再跑 `--valuation.init`（幂等，可重复执行）
