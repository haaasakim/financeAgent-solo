## 1. 目标与范围

**目标**：回测调仓频率新增「每日」，即每个交易日收盘求值、次日开盘成交，供高频调仓策略验证。

**范围内**：`RebalanceFrequency` 枚举与信号日逻辑；回测表单频率选项；引擎单测；真实数据端到端验证。

**范围外**：不放宽无未来函数约束（信号仍为 T 日收盘、成交 T+1 开盘）；不改变费用、涨跌停、停牌、整手口径；不做性能优化（每日全市场截面耗时随区间线性增长，属已知取舍）。

## 2. 契约

- 调仓频率新增 `DAILY`（每日）：区间内**每个交易日收盘 T 都是信号日**，成交在 T+1 开盘；最后一个交易日无 T+1，不产生订单。其余撮合、费用、涨跌停、停牌与整手规则与 WI-006 完全一致。
- API：`POST /fragments/backtest/run` 的 `frequency` 新增取值 `DAILY`；默认仍为 `MONTHLY`；非法值仍抛「调仓频率不合法」。
- 无数据库结构变更；频率已随参数保存于 `backtest_task.params_json`。

## 3. 数据语义

| 项 | 值 |
|---|---|
| 市场 / 币种 / 时区 | 同 WI-006（A 股 / CNY / Asia/Shanghai） |
| 复权方式 | 前复权（qfq） |
| 数据来源 | 同 WI-006，无新增数据源 |
| 可用时点 available_at | 信号日 T 收盘；因子与估值取 T 日截面 |
| 单位与精度 | 同 WI-006 |

## 4. 实现要点

- `RebalanceFrequency` 增加 `DAILY("每日")`，`from()` 默认值不变。
- `BacktestEngine.crossesPeriod`：`DAILY` 恒真 → `signalDates` 收集区间内全部交易日。
- 回测表单下拉新增「每日」（默认仍「每月」）。
- 交易记录展示与排序沿用现有「按标的配对 / 订单流水」。

## 5. 异常、幂等与回滚

- 异常与失败处理：同 WI-006（任务级 FAILED，原因落库）。
- 幂等性：同一任务不重复执行；重复提交生成新任务，结果按任务 id 归属。
- 迁移与回滚：无迁移。回滚只需移除页面选项与枚举分支；历史任务 `params_json` 不受影响。

## 6. 验证

**验收标准**：每日频率下每个交易日生成信号、成交严格 T+1；既有撮合规则不回归；页面可提交并展示结果。

## 7. 未验证项与剩余风险

- 每日频率换手极高（实测年化 5025%），交易费用对结果影响大，策略对比时需注意。
- 每个信号日做一次全市场截面查询与评分，耗时随区间线性增长（实测 169 交易日约 9s）；10 年以上长区间单任务可能到分钟级，尚未做缓存/并行优化。
- 每日频率未新增特殊边缘逻辑，但真实数据下极端连续涨跌停的延后链条比月频更长，仅由既有规则兜底。
