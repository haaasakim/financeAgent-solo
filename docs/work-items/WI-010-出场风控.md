# WI-010 回测出场风控（固定止损 / 时间止损）

> 在 WI-009 固定 N 槽等权基础上增加出场风控。基线策略（超跌企稳）的尾部亏损来自慢跌持仓
> （如广聚能源、山河智能被持有约 2 个月、亏损 20% 后被轮换卖出），本工作项用止损与时间止损封顶单笔亏损。

## 1. 目标与范围

**目标**：回测支持两类出场规则，当日收盘触发、T+1 开盘卖出（沿用涨跌停 / 停牌延后）：

1. **固定止损** `stopLossPct`（百分比，0 关闭）：收盘价 ≤ 持仓含费成本价 × (1 − 止损率) → 卖出。
2. **时间止损** `timeStopDays`（交易日，0 关闭）：持有交易日数 ≥ N 且收盘价 < 持仓含费成本价（未盈利）→ 卖出。

止损卖出的标的进入禁买集合：在该标的仍处于目标集合期间不再买回；直到它不再出现在目标集合后解除。

**范围内**：

- `BacktestEngine` 出场检查、禁买集合、与调仓的订单冲突处理；`Order` / `Position` 补充字段。
- 参数 `stopLossPct`、`timeStopDays` 全链路：表单、`BacktestRequest`、`BacktestParams`（`params_json`）、校验与回显。
- 成交记录在 `reason` 标注卖出类型（止损卖出 / 时间止损），便于复盘。
- 单元测试与真实数据验证。

**范围外**：

- 移动止损（回撤止盈）、组合级风控、按板块差异化的止损阈值。
- 修改入场选股、调仓频率、费用、涨跌停、停牌、整手与 WI-009 建仓口径。
- 历史任务不回填；新建任务 `engine_version=3`。

## 2. 契约

**触发与执行**：

- 每个交易日流程：执行挂单（开盘）→ 出场检查（收盘）→ 信号日调仓。
- 出场检查对每个持仓（已有卖单挂起的除外）用当日收盘价判断；触发即生成卖单，信号日 = 当日、执行日 = 下一交易日。
- 成本口径 = 持仓含费成本 ÷ 股数（与卖出盈亏、胜率口径一致）。
- 同日同时触发两类规则：记「止损卖出」（固定止损优先）。
- 一字跌停 / 停牌无法卖出 → 沿用延后规则；期末未成交 → EXPIRED（原因「期末未成交」）。
- **禁买集合**：止损卖单生成时加入；后续调仓中跳过该标的的买入；当该标的不再出现在目标集合时移除。
- **订单冲突**：止损卖单不被调仓取消（即使标的仍在目标集合）；调仓不会重复生成卖单。

**API / 表单**：

| 参数 | 默认（表单） | 校验 |
|---|---|---|
| `stopLossPct`（%） | 12 | 0 ~ 50，0 关闭 |
| `timeStopDays`（交易日） | 0 | 0 ~ 250，0 关闭 |

- `POST /fragments/backtest/run` 新增上述参数；旧任务 `params_json` 无字段时回显 0（关闭）。
- `backtest_trade.reason`：FILLED 卖单可标注「止损卖出」/「时间止损」；EXPIRED 仍记未成交原因。

## 4. 实现要点

- `BacktestEngine.run`：新增 `stoppedIds`；执行挂单后调用 `checkStops(...)`，再进入调仓；调仓跳过禁买标的并在标的离开目标集合时解除禁买。
- `checkStops`：按收盘价与含费成本比较；生成带 `note` 的卖单；无持有成本、已挂卖单、收盘价缺失时跳过。
- `Position` 增加 `entryDate`（买入成交日），持有交易日数按回测交易日序列下标差计算。
- `Order` 增加 `note`：FILLED 时写入 `reason`，止损卖单标记类型；调仓取消逻辑只取消非止损卖单。
- `BacktestService`：参数校验与换算（百分比 → 小数）；`ENGINE_VERSION = "3"`。
- 表单与回显：新增两个输入；历史任务缺字段回显 0。

## 5. 异常、幂等与回滚

- 异常与失败处理：同 WI-006；参数越界抛用户可见异常。
- 幂等性保证：同一任务重复执行结果一致。
- 迁移与回滚：无数据库结构变更；回滚只需关闭两个参数（0）即可回到 WI-009 行为；历史任务 `engine_version` 可区分。

## 7. 未验证项与剩余风险

- 止损会把「继续下探后反弹」的均值回归票也割掉，可能降低胜率或收益；阈值需用真实数据对比后取舍。
- 一字跌停 / 停牌导致的延后仍可能出现超过阈值的实际亏损（无法成交）。
- 禁买集合使用「当前名称」与目标集合判断，不做时间冷却；趋势型策略需另行评估。
