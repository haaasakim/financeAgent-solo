## 1. 目标与范围

**目标**：实现技术指标纯函数库与 `factor_daily` 因子宽表，提供全量回填与增量重算任务，
为 M4 选股（趋势 / 风险类条件）提供毫秒级预计算查询。

**范围内**：

- `indicator` 纯函数包：MA、MACD、RSI、N 日收益、波动率、距 52 周高点
- V3 迁移：`factor_daily` 宽表 + `trade_date` 索引
- `FactorDaily` record + Mapper（upsert / 计数 / 已有因子的标的集合）
- `--factor.init` 全量回填、`--factor.update` 增量重算
- `--sync.incremental` 末尾自动衔接因子增量
- 指标对拍测试、Mapper 真实 SQLite 测试、Service 幂等与 warmup 测试

**范围外**：

- 财务因子（PE / PB / ROE / 营收同比等）：依赖财务报表数据源，尚未同步，待其入库后另立工作项
- 选股 DSL 与条件求值（M4）
- 详情页图表均线改由服务端下发（前端仍自行计算，纯展示逻辑）
- 分钟级指标、指标参数用户自定义

## 2. 契约

### 2.1 表结构（迁移 V3）

**factor_daily** 因子宽表，主键 `(instrument_id, trade_date)`。

| 列 | 类型 | 说明 |
|---|---|---|
| instrument_id | TEXT | PK(1/2) |
| trade_date | TEXT | PK(2/2)，`YYYY-MM-DD` |
| ma5 / ma10 / ma20 / ma60 | REAL | 前复权收盘简单均线，元 |
| macd_dif / macd_dea / macd_hist | REAL | MACD(12,26,9)，元，`hist = dif - dea`（**不乘 2**） |
| rsi6 / rsi12 / rsi24 | REAL | Wilder RSI，0~100 |
| return_20 / return_60 | REAL | N 个交易日收益，小数（0.125 = 12.5%） |
| volatility_20 | REAL | 最近 20 个日收益率的标准差，小数，**未年化** |
| pct_from_52w_high | REAL | `close / 近 250 根 bar 最高收盘 - 1`，小数，≤ 0 |
| data_status | TEXT | NOT NULL DEFAULT `ACCEPTED` |
| created_at / updated_at | TEXT | NOT NULL |

索引：`idx_factor_daily_date(trade_date)`。

### 2.2 指标口径（全部基于前复权收盘价，按标的自身 bar 序列计算）

以 `t` 为当前 bar 在其自身序列中的下标：

| 指标 | 公式 / 参数 | 缺失（NULL）条件 |
|---|---|---|
| MA(N) | `mean(close[t-N+1..t])` | 序列长度 < N |
| MACD | `EMA(12)`、`EMA(26)` 以首根收盘播种，`DIF=EMA12-EMA26`，`DEA=EMA(DIF,9)` 同法播种，`HIST=DIF-DEA` | 无（首根即有值，早期值不稳定但确定） |
| RSI(N) | Wilder 平滑：首个均值为前 N 个涨跌均值，其后 `avg=(avg*(N-1)+x)/N`；`RSI=100-100/(1+avgGain/avgLoss)` | 序列长度 < N+1 |
| return_N | `close[t]/close[t-N]-1` | 序列长度 < N+1 |
| volatility_20 | 最近 20 个 `close[i]/close[i-1]-1` 的样本标准差（n-1） | 序列长度 < 21 |
| pct_from_52w_high | `close[t]/max(close[t-249..t])-1` | 序列长度 < 250 |

边界约定（契约级，测试必须覆盖）：

- 停牌 / 缺失日**不对齐日历**：以该标的自身的 bar 序列滚动，缺口自然跳过
- RSI 中 `avgLoss=0 且 avgGain>0` → 100；`avgGain=0 且 avgLoss>0` → 0；两者同为 0（横盘）→ 50
- 波动率输入为日收益率，分母 n-1；标的价格不足或存在 0 价时不产生负值（价格为正）
- 回看不足的因子列保持 NULL，**禁止以 0 或哨兵值填充**

### 2.3 任务接口

| 任务名 | CLI | 语义 |
|---|---|---|
| `FACTOR_INIT` | `--factor.init` | 对已有日K的标的全历史计算并 upsert |
| `FACTOR_UPDATE` | `--factor.update` | 有因子记录的标的只重算最近 260 根 bar；从未算过的自动转全量 |

- `FACTOR_UPDATE` 取最近 **510** 根 bar 作为计算切片（260 输出 + 250 最长回看），仅 upsert 尾部 260 行，
  避免切片头部因回看不足把历史正确值覆盖成 NULL
- 切片播种 EMA 与全量播种存在理论差异：510 根后种子影响约 `(25/27)^250 ≈ 4e-9`，
  远低于 0.01 元报价精度；实测尾部因子与全量回填结果一致
- `--sync.incremental` 执行成功后自动衔接一次 `FACTOR_UPDATE`
- 批量 upsert 每 500 行一批；进度每 500 只标的记 INFO；结束写 `sync_log`

## 3. 数据语义

| 项 | 值 |
|---|---|
| 市场 / 币种 / 时区 | A 股 / CNY / Asia/Shanghai |
| 复权方式 | 前复权（QFQ），与 `daily_bar` 同口径 |
| 数据来源 | 本地 `daily_bar` 派生，无外部请求 |
| 可用时点 available_at | 对应交易日收盘后（与日K一致），仅用当日及之前数据 |
| 单位与精度 | 均线/MACD=元；RSI=无量纲；收益/波动/距高点=小数 |

## 4. 实现要点

1. `indicator` 包为**纯函数**：入参 `double[]` / `Double[]`，无 Spring、无 I/O、无时钟依赖。
2. 缺失用 `Double` 的 null 表达（`Double[]`），不使用 NaN 哨兵泄漏到持久层。
3. `FactorCalculator` 一次遍历组装全部因子列，避免每因子重复求值。
4. `FactorDailyMapper.upsertBatch` 走 `ON CONFLICT (instrument_id, trade_date) DO UPDATE` 保证幂等。
5. 同步审计复用 `SyncLogRecorder`（从 `MarketDataSyncService` 抽出的公共组件）。
6. 验证入口：页面 `GET /market/factors?instrumentId=...&limit=...`（个股详情页有「技术因子」入口），
   JSON `GET /api/factors/{instrumentId}?limit=...`（交易日倒序，供脚本对拍）。

## 5. 异常、幂等与回滚

- **异常**：因子计算为本地纯计算，不产生网络异常；单标的计算失败（如空 bars）跳过并计入 fail。
- **幂等**：upsert 覆盖；重复执行行数不变。`FACTOR_UPDATE` 只覆盖最近窗口，更早历史不被触碰。
- **回滚**：新增表与代码，不改动已有数据。回滚 = 回退提交；`factor_daily` 可 DROP 后由 `--factor.init` 重建。

## 7. 未验证项与剩余风险

- 日K仅补齐部分标的（数据状态），因子只覆盖已同步标的
- MACD 采用「首根播种」实现，早期数值与部分行情软件（SMA 播种）存在差异，契约以本文件为准
- 52 周高点按 250 根 bar 计算，不足 250 根的新股该列为 NULL
- 财务因子与「排除 ST / 停牌 / 上市天数」等基础条件由 M4 结合 `instrument` 表与状态实现
- 增量重算依赖「有因子记录」判定是否已回填；若人为删除了某标的尾部因子但保留头部，update 仍只重算窗口，需用 `--factor.init` 修复
