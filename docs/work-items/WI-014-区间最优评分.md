## 1. 目标与范围

**目标**：为「温和 / 适中」类因子补充**区间最优**评分——目标区间内满分，区间外按偏离距离线性衰减，
上侧与下侧可设不同容差；解决单调方向（越大/越小越好）无法表达「不追高、温和放量」的问题
（例：策略 69 的量比 `higher` 会把放量最猛的排最前）。

**范围内**：

- DSL 条件新增可空字段：`bandLow` / `bandHigh` / `bandLowTolerance` / `bandHighTolerance`，
  `direction` 新增取值 `"band"`（见 §2.1）
- `DslValidator`：区间字段校验（见 §2.3）
- `ScreenerService`：区间子分公式，与百分位子分加权合成（选股 / 回看 / 回测共用）
- 选股页：评分方向下拉增加「区间最优」，选中后展开区间与两侧容差输入
- 策略 JSON：旧策略无新字段、行为与哈希不变；新字段仅随 `direction="band"` 出现
- 测试：公式手算对拍（对称 / 不对称 / 理想值）、校验失败、回看与页面共用路径、旧 JSON 回归

**范围外**：

- 区间作为过滤条件（过滤仍由现有 `gte`/`lte` 等条件完成）
- 高斯 / 对数等非线性衰减；独立的「目标值 + 容差」模式（`bandLow == bandHigh` 即理想值）
- 评分分布口径变化（仍为 0~1 子分加权平均 ×100）
- 自动推荐区间或按 IC/IR 推导参数

## 2. 契约

### 2.1 DSL v3 字段（单条数值条件）

```json
{"factor":"volumeRatio20","op":"gte","value":1.2,"score":true,"weight":1,"direction":"band",
 "bandLow":1.2,"bandHigh":2.0,"bandLowTolerance":0.5,"bandHighTolerance":0.5}
```

| 字段 | 类型 | 缺省 | 语义 |
|---|---|---|---|
| `direction` | `"higher"` / `"lower"` / `"band"`，可空 | 由运算符推断；`eq` 无默认 | `band` = 区间最优评分 |
| `bandLow` / `bandHigh` | number，可空 | 无 | 目标区间 `[low, high]`，允许 `low == high`（理想值） |
| `bandLowTolerance` | number > 0，可空 | 无 | 低于 `low` 后每偏离该距离，子分从 1 线性降到 0 |
| `bandHighTolerance` | number > 0，可空 | 无 | 高于 `high` 后每偏离该距离，子分从 1 线性降到 0 |

### 2.2 评分公式

- 区间子分：`low ≤ x ≤ high` → `1`；
  `x < low` → `max(0, 1 - (low - x) / bandLowTolerance)`；
  `x > high` → `max(0, 1 - (x - high) / bandHighTolerance)`。
- 总评分与 WI-011 相同：`100 × Σ(wᵢ·sᵢ) / Σ(wᵢ)`（`sᵢ` 为百分位或区间子分，均为 0~1），
  保留 1 位小数；无参与条件或取值全为 NULL 时为 NULL。
- 方向为 `higher` / `lower` 时行为与 WI-011 完全一致；兼容模式（无 `score` 字段）不产生 `band`。
- 区间评分是**绝对口径**（只依赖因子原始值与参数），不随命中集变化；与相对百分位子分可直接加权混合。

### 2.3 校验规则（DslValidator）

| 场景 | 结果 |
|---|---|
| `direction="band"` 缺 `bandLow` / `bandHigh` / 任一容差 | 拒绝：区间参数缺失 |
| `bandLow > bandHigh` | 拒绝：区间下限不能大于上限 |
| 容差非有限或 `≤ 0` | 拒绝：区间容差必须大于 0 |
| 区间参数非有限或绝对值超过 1,000,000 | 拒绝：区间参数超出允许范围 |
| `score != true` 且出现任一区间字段 | 拒绝：只有参与评分的条件才能设置区间参数 |
| `direction != "band"` 且出现任一区间字段 | 拒绝：非区间评分不能设置区间参数 |
| `direction="band"` 且 `op=eq` | 允许（方向已显式给出） |
| 布尔条件 / 排除组携带区间字段 | 沿用 WI-011 拒绝（不支持评分） |

### 2.4 数据语义与兼容

| 项 | 值 |
|---|---|
| 评分时点 | 与 WI-011 相同：筛选同一截面（页面为最新，回看 / 回测按 `asOf`） |
| 持久化 | 不落库；随策略 JSON 保存；旧策略无新字段、无需迁移 |
| 哈希 | `StrategyHash` 基于 DSL JSON：旧策略哈希不变；新区间字段参与哈希 |
| 回退 | 纯代码 + 前端改动，无数据迁移；回退代码后旧代码 `@JsonIgnoreProperties` 忽略区间字段，策略退化为不含 band 的评分 |

## 3. 实现要点

1. `Condition` 增加 4 个可空字段，保留 3 参与 6 参构造器；`ScoreDirection` 增加 `BAND("band")`。
2. `DslValidator` 扩展评分字段校验（§2.3）。
3. `ScreenerService.ScoringCondition` 携带区间参数；`score()` 按方向分支计算子分。
4. 前端 `screenerApp`：`hydrate`/`compile` 透传区间字段；方向切换为 `band` 时给默认值；
   条件行仅在该方向下渲染区间输入。
5. 选股页 / 回看 / 回测共用同一评分路径，无独立实现。

## 4. 异常、幂等与回滚

- **异常**：校验失败抛 `BusinessException`（页面提示）；查询失败走 `WebExceptionHandler`。
- **幂等**：纯查询评分，重复执行结果一致。
- **回滚**：回退代码即可；已保存的带区间字段策略在旧代码下按无区间参数处理（忽略未知字段）。

1. `./mvnw test` 全绿；`./mvnw clean package` 构建通过
2. 区间公式与手算一致（对称 / 不对称 / `low == high` / 超出容差为 0）
3. 区间子分与百分位子分加权混合结果与手算一致
4. 回看 `evaluateAt` 与页面 `screen` 用同一 DSL 排序一致
5. 旧策略 JSON（无区间字段）评分 / 排序与 WI-011 用例一致（回归）
6. 页面：方向下拉含「区间最优」，选中后区间输入渲染，1440 / 768 无溢出

## 6. 未验证项与剩余风险

- 区间与容差靠人工设定，无数据驱动依据
- 「命中集内相对百分位」与「绝对区间」混合时，两类子分的可比性依赖用户理解
- 页面交互需真实浏览器复核（1440 / 768）；截面上命中的 ETF（如科创债 ETF）
  也会参与区间评分，策略如需仅股票需自行加条件（暂无标的类型因子）
- 迁移后的策略回测效果尚未跑通（评分路径与回测共用，已由单测覆盖），建议迁移后重跑一次确认
