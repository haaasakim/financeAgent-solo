# 前端约束

> 状态：设计定稿（一期）
> 本项目前后端不分离，页面由 Spring Boot 服务端渲染。本文约束 `src/main/resources/` 下的模板与静态资源。

## 1. 技术选型与边界

| 技术 | 用途 | 边界 |
|---|---|---|
| Thymeleaf | 服务端渲染 HTML | 唯一页面渲染方式 |
| HTMX | 局部刷新（分页、排序、筛选、轮询） | 不做整页路由 |
| Alpine.js | 纯前端交互状态（条件增删、弹窗、折叠） | **不发起数据请求** |
| ECharts | K线、净值、回撤、分布图 | 本地引入，不走 CDN |

**不引入 Node 构建链**：没有 npm、没有打包器、没有 TypeScript。所有 JS 库以静态文件放入 `static/js/`，由模板直接引用。这是刻意的取舍——个人项目的收益不足以覆盖构建链的维护成本。

## 2. 目录结构

```
src/main/resources/
├── templates/
│   ├── layout/                页面骨架（head、导航、页脚片段）
│   ├── market/                市场模块页面
│   ├── screener/              选股模块页面
│   ├── backtest/              回测模块页面
│   └── fragments/             HTMX 局部片段（图表、表格、进度、错误）
├── static/
│   ├── css/app.css            全站样式（单一文件，CSS 变量组织）
│   ├── js/echarts.min.js      图表库
│   ├── js/htmx.min.js         局部刷新
│   ├── js/alpine.min.js       交互
│   └── js/app.js              本项目自定义逻辑（图表初始化等）
└── application.yml
```

## 3. Thymeleaf 约定

- 布局用 `th:fragment` + `th:replace` 组合，片段文件以 `_` 前缀或无前缀明确归类，禁止在页面里复制导航与页脚。
- 所有动态文本用 `th:text`，**禁止 `th:utext`**（防 XSS），除非内容来自受信来源且已明确注释说明。
- 拼 URL 统一用 `th:href="@{/market/stock(code=${code})}"`，不手写字符串拼接。
- 金额、百分比、数量统一走格式化工具（`#numbers.formatDecimal`），**展示格式化只发生在模板层**，不改变存储值。
- 空值展示为 `--`，不展示 `null` 或 `0`。

## 4. HTMX 约定

HTMX 负责所有「不跳页的刷新」。统一约定：

| 场景 | 用法 |
|---|---|
| 表格分页 / 排序 / 筛选 | `hx-get` 指向片段路由，`hx-target` 指向表格容器 |
| 表单提交 | `hx-post` + `hx-target` 指向结果区 |
| 任务进度轮询 | `hx-get` + `hx-trigger="every 2s"`，任务结束后服务端返回不带轮询属性的片段以停止 |
| 加载指示 | 必须配置 `hx-indicator`，禁止无反馈的静默刷新 |

约束：

- HTMX 请求返回的**必须是片段**，不能是完整页面（含 `<html>` 标签）。
- 片段路由统一放在 `/fragments/**` 下，与页面路由分离。
- 局部刷新区域的 DOM 结构必须稳定，避免 HTMX 替换后丢失 Alpine 状态。
- 参数传递优先用 `hx-include` 收集表单，不在 URL 里手写冗长参数。

## 5. ECharts 规范

- 图表实例统一在 `app.js` 中初始化和销毁，页面模板只提供一个带 `id` 的容器和一份 JSON 数据。
- 数据通过 `th:inline="javascript"` 注入，或由容器上的 `data-*` 属性承载。
- 必须处理：**窗口 resize 重绘**、**切换标的后销毁旧实例**（防内存泄漏）。
- 统一配置：禁用动画或缩短至 300ms 以内；`grid` 留白统一；`tooltip` 统一 `axis` 触发。
- 均线颜色与 K 线涨跌色区分，不使用同色系。

一期图表清单：

| 图表 | 类型 | 位置 |
|---|---|---|
| K线 + 均线 + 成交量 | candlestick + line + bar 副图 | 个股详情 |
| 净值曲线（策略 vs 基准） | line 双序列 | 回测结果 |
| 回撤曲线 | area | 回测结果 |
| 指标卡（非图表） | 纯 CSS | 回测结果 |

## 6. 配色与视觉

**涨跌配色遵循中国习惯：涨红、跌绿。** 这与欧美相反，必须严格遵守。

| 语义 | 色值 | 说明 |
|---|---|---|
| 涨 | `#D9363E` | 红色 |
| 跌 | `#1D9E75` | 绿色 |
| 平 / 未知 | `#888780` | 灰色 |
| 主色（交互） | `#185FA5` | 导航、按钮、链接 |
| 背景 | `#F7F7F5` | 页面底色 |
| 卡片 | `#FFFFFF` | 内容容器 |

其他约定：

- 浅色主题为主，金融终端式的紧凑信息密度。
- 颜色统一在 `app.css` 用 CSS 变量定义，模板与 JS 不写死色值。
- 中文界面，字体栈包含 `PingFang SC`、`Microsoft YaHei`。
- 数字统一使用等宽字体并右对齐，便于纵向比较。
- 不使用渐变、阴影堆叠等装饰性效果。

## 7. 三个页面的布局

**市场页**：顶部导航 → 市场概览条（指数行情）→ 全市场标的表格（可排序、可筛选、分页）。表格列：代码、名称、最新价、涨跌幅、成交额、换手率、PE、市值。

**选股页**：左右两栏。左侧为**因子目录树**（按基础/估值/质量/成长/趋势/风险分组）与预设策略列表；右侧为**条件卡片列表**，支持「全部满足 / 任一满足 / 排除」三种逻辑容器。底部为结果表格，支持一键「保存为策略」与「拿去回测」。

规则树在界面上必须呈现为**可读的卡片列表**，不向用户暴露 JSON。

**回测页**：上部参数表单（策略、区间、调仓频率、持仓数、初始资金、费率、基准）→ 中部任务进度 → 下部结果区（指标卡、净值曲线、回撤曲线、交易流水表格）。

## 8. 组件约定

| 组件 | 要求 |
|---|---|
| 数据表格 | 表头可排序（HTMX），空数据展示空状态而非空白，数值列右对齐 |
| 分页 | 显示总数、当前页、页大小选择；用 HTMX 局部刷新 |
| 条件卡片 | 每张卡片 = 一个因子 + 运算符 + 值；可删除；参数只允许从服务端下发的选项中选 |
| 指标卡 | 数值 + 标签 + 涨跌色；数值单位明确（如年化收益率） |
| 任务进度 | 进度条 + 已处理/总数 + 当前状态；失败时展示错误摘要 |
| 提示信息 | 成功/失败提示统一用页面顶部条状提示，不用 `alert()` |

## 9. 状态处理

每个数据区域必须实现四种状态，缺一不可：

| 状态 | 表现 |
|---|---|
| 加载中 | 骨架屏或加载指示器（HTMX `hx-indicator`） |
| 有数据 | 正常渲染 |
| 空数据 | 明确文案说明原因（如「该标的无 10 年数据，可能上市不足」） |
| 错误 | 展示错误摘要 + 重试按钮，不展示堆栈 |

**禁止**：空白页面、无限转圈、把异常堆栈直接渲染到页面。

## 10. 响应式

- 断点：`1440`（主）、`1024`、`768`。
- 主战场是桌面浏览器，移动端只需可用，不做专项适配。
- 表格在窄屏下允许横向滚动，**禁止压缩到数字折行**。
- 图表容器使用百分比宽度，配合 resize 重绘。

## 11. 静态资源版本管理

- 引入静态资源时带版本查询串（如 `app.css?v=1`），避免浏览器缓存导致改动不生效。
- 第三方库升级必须同时更新文件与版本号，并在提交信息中说明来源与版本。
